# Semantic Chat Search — Implementation TODO

Persistent, git-tracked checklist for adding project-scoped semantic chat
search over video transcripts: embeddings + Postgres full-text search +
reranking, orchestrated by a PydanticAI agent with a search tool, producing a
synthesized answer whose citations render as jump-to-transcript preview
cards. Stands alongside `TODO.md` (read `backend/CLAUDE.md` and the
repo-root `CLAUDE.md` first — same rules apply: fully typed, `mypy --strict`
clean, ruff clean, TDD, test tree mirrors source tree, explicit imports, no
`__all__`, autogenerated migrations only, `make check` green at the end of
every phase).

Design record: `/Users/jan/.claude/plans/in-this-project-i-eager-eagle.md` —
read it first for full rationale on every decision below; this checklist is
the concrete execution of that plan.

**Scope change**, recorded here per the project's existing convention (cf.
`TODO.md` Phase 10's DeepL→Argos note): `docs/100_product_spec.md` §16 and
`docs/300_architecture.md` §15 currently list "semantic search"/"AI
processing services"/"vector databases" as out of scope for v1 — this
feature supersedes that. Phase S7 updates those doc sections; don't leave
them contradicting the shipped feature.

Confirmed decisions (see the design record for the "why" behind each — do
not re-litigate these while implementing):
- **Answer mode**: a synthesized prose answer with structured citations, not
  a bare ranked list. Citations render as rich, seekable preview cards, not
  plain links.
- **Providers**: all AI calls go through **OpenRouter**, one
  `OPENROUTER_API_KEY`. Chat/agent model and embeddings go through
  PydanticAI's built-in OpenRouter/OpenAI-compatible support; reranking has
  no PydanticAI abstraction, so it's a small hand-rolled `httpx` client.
- **Agent**: built with **PydanticAI** — one `Agent` with one tool,
  `search_transcripts`, and a structured `ChatAnswer(answer, citations)`
  output type. No separate deterministic query-reformulation step; the agent
  decides when and how to re-query.
- **Models (v1 default)**: agent `openrouter:google/gemini-flash-latest`
  (cheap, always-current Flash-tier alias); embeddings
  `openai/text-embedding-3-small` (1536-dim); rerank `cohere/rerank-v3.5`.
  All via OpenRouter.
- **Chunking**: one chunk per `TranscriptSegment`; segments over ~800 chars
  sub-split into multiple same-segment chunks (no cross-segment windows).
- **Multilingual handling**: every transcript (original + translations) gets
  embedded, for recall in either language. Citations always **resolve to the
  original-language transcript's chunk** for the matched moment, even if a
  translation chunk scored best — matches `VideoWorkspace.tsx`'s existing
  "left pane always shows the original transcript" convention.
- **Full-text search on chunks**: `transcript_chunks.search_vector` is a
  plain (not DB-generated) `TSVECTOR` column, populated by the embedding job
  using a language-aware Postgres text-search config (not hardcoded
  `'english'` like the existing token-level search — original transcripts
  may not be English).
- **Scope**: per-project only, same `require_project_member` authorization
  as the existing search feature.
- **Re-embedding**: no live re-embed on token edits. Auto-embed once after
  transcription/translation completes, plus an explicit reindex endpoint for
  manual refresh after heavy edits.
- **Sync, not streaming**: the chat endpoint is a synchronous request/response
  (no SSE/WebSocket exists anywhere in this stack); citations are validated
  server-side before the client ever sees them.

## Phase S4 — Agent + retrieval service (PydanticAI)
- [x] `backend/app/services/chat_retrieval.py`: `search_chunks(session, project_id, query) -> list[TranscriptChunk]` — embeds `query` via `get_embeddings_provider()`, runs a pgvector `<=>` ANN search (`ORDER BY embedding <=> :qvec LIMIT K`) and a `plainto_tsquery` FTS search against `transcript_chunks.search_vector`, both scoped by `project_id`; unions/dedups the two candidate sets by chunk id; reranks the union via `get_rerank_provider()`, sorts descending, takes top ~8; for each winner, if it belongs to a translation transcript, looks up and substitutes the **original transcript's chunk** covering the same `(video_id, start_time, end_time)` (collapsing same-moment duplicates across languages in the process). Returns original-language chunks only, highest-ranked first
- [x] `backend/app/agents/transcript_search.py`: `ChatDeps` dataclass (`session: Session`, `project_id: uuid.UUID`, `seen_chunk_ids: set[uuid.UUID]` defaulting empty); `ChunkResult`/`Citation`/`ChatAnswer` Pydantic models (`ChatAnswer{answer: str, citations: list[Citation]}`, `Citation{marker: int, chunk_id: uuid.UUID}`); `transcript_agent = Agent(settings.chat_agent_model, deps_type=ChatDeps, output_type=ChatAnswer, system_prompt=...)` with a system prompt instructing it to search the project's transcripts via the tool (calling it again with different phrasing if the first search doesn't turn up enough — this replaces a fixed query-reformulation step) and to **only cite `chunk_id`s the tool actually returned**; `@transcript_agent.tool def search_transcripts(ctx: RunContext[ChatDeps], query: str) -> list[ChunkResult]` calling `search_chunks`, recording every returned id into `ctx.deps.seen_chunk_ids`, and mapping to `ChunkResult` (chunk_id, video_name, speaker_name, start_time, text) for the model to read
- [x] Run synchronously via `agent.run_sync(question, deps=..., message_history=...)` — do not introduce an async DB session layer for this; it must fit the codebase's existing sync `Session`/route style
- [x] `backend/app/services/chat.py`: `answer_question(session, project_id, conversation_id, question) -> ChatMessage` — loads or creates the `ChatConversation`; if `agent_message_history` is set, deserializes it via PydanticAI's `ModelMessagesTypeAdapter`; builds `ChatDeps(session, project_id)`; calls `transcript_agent.run_sync(...)`; filters `result.output.citations` to those whose `chunk_id ∈ deps.seen_chunk_ids` (hallucination guard — drop the rest); resolves each surviving citation's `chunk_id` to full display metadata (video name, folder path, timecode, excerpt, speaker) for persistence/response; persists a `"user"` `ChatMessage` then an `"assistant"` `ChatMessage` (with resolved `citations` JSONB); updates `ChatConversation.agent_message_history` from `result.all_messages()`; returns the assistant message
