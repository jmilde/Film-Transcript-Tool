# Document Builder UX Consistency Overhaul — Implementation TODO

Persistent, git-tracked checklist for making the Document Builder feature
(`TODO_DOCUMENT_BUILDER.md`, phases D1–D8 done) consistent with the existing
transcript-editing UX: resizable panels, highlight-and-comment in document
prose, a shared "what can I do with this selection" popup, an
insertion-point marker settable from the document that survives navigating
back to the transcript, link-preserving copy/paste from transcript into
document, a uniform video player, and unified comments across transcript
and document. Stands alongside `TODO.md`, `TODO_SEMANTIC_SEARCH.md`, and
`TODO_DOCUMENT_BUILDER.md` (read `backend/CLAUDE.md` and the repo-root
`CLAUDE.md` first — same rules apply: fully typed, `mypy --strict` clean,
ruff clean, TDD, test tree mirrors source tree, explicit imports, no
`__all__`, autogenerated migrations only, `make check` green at the end of
every backend phase).

Design record: `/Users/jan/.claude/plans/i-want-to-improve-witty-glacier.md`
— read it first for full rationale on every decision below; this checklist
is the concrete execution of that plan.

Confirmed decisions (see the design record for the "why" behind each — do
not re-litigate these while implementing):
- **Comments: fully unified.** One `Comment` entity with a polymorphic
  anchor — either a transcript token range (existing `CommentRange`) or a
  document anchor (a TipTap `comment` mark on a run of prose text, or a
  `clipBlock` node's stable `nodeId`). One shared comments UI renders both,
  filtered to whichever context is active.
- **Panels: merged.** The document panel becomes a true resizable peer of
  the routed page inside one `react-resizable-panels` `Group` owned by
  `AppShell` (not a separate fixed-width sidebar). `VideoWorkspace` keeps
  its own nested transcript/video `Group` inside that outer page panel.
- **Editor:** keep TipTap WYSIWYG with markdown-style input shortcuts (no
  raw-markdown-source-view toggle). Fix that `# `/`## ` don't currently
  render as visually distinct headings (missing `@tailwindcss/typography`
  plugin registration). Add a real selection/formatting toolbar
  (bold/italic/heading levels) rather than relying on typed shortcuts
  alone — this toolbar is the same shared component used for the
  transcript's selection actions and the document's comment/clip popup.
- **Clip references: inline text, not cards.** `clipBlock` changes from a
  block-level `atom` node (rendered as a thumbnail/timecode card) to an
  **inline** `atom` node — still non-editable/read-only, excerpt still
  resolved fresh server-side, never persisted — rendered as styled inline
  text within the document's normal paragraph flow, not a boxed card.
- **Clip vs. comment visual channels don't collide.** A persistent left
  border + subtle background tint marks "this text is from source
  material" (clips); the underline decoration (violet = unresolved,
  slate = resolved, exactly as in the transcript today) is reserved
  exclusively for comments, in both transcript and document. The two
  layers stack independently — a clip with a comment on it shows both at
  once.
- **Clip "note" field is retired.** Per-clip notes fold into the unified
  comment system instead of staying a separate always-visible input — a
  note becomes a normal `Comment` row anchored via
  `DocumentCommentAnchor.clip_node_id`.
- **Insertion-point marker is a live ProseMirror plugin position, not a
  stored offset.** Never persist a raw position integer anywhere (Zustand
  included) — it goes stale on the next edit. The marker lives in the
  editor instance's own plugin state, mapped through every transaction
  exactly like the comment mark; it survives navigating to the transcript
  because `DocumentPanel`/`DocumentEditor` are already mounted persistently
  in `AppShell` and never unmount on route/focus changes.
- **Clipboard interop uses `text/html` + `text/plain`, not a custom MIME
  type** (custom `ClipboardItem` types have inconsistent cross-browser
  safelisting; `text/html`/`text/plain` are universal and `text/plain` stays
  byte-for-byte identical to today's behavior, so external paste is
  unaffected).
