# Document Builder — Implementation TODO

Persistent, git-tracked checklist for adding a project-scoped **Document
Builder**: users create one or more named documents per project, mixing
their own prose with embedded, non-editable clip blocks (structured
references to a transcript token range + video, resolved fresh on read),
reachable from a persistent global panel so clips can be inserted while
browsing a transcript, a search result, or a chat citation without leaving
the page. This replaces the current workaround of keeping a separate Google
Doc open and copy-pasting transcript text into it. Stands alongside
`TODO.md` and `TODO_SEMANTIC_SEARCH.md` (read `backend/CLAUDE.md` and the
repo-root `CLAUDE.md` first — same rules apply: fully typed, `mypy --strict`
clean, ruff clean, TDD, test tree mirrors source tree, explicit imports, no
`__all__`, autogenerated migrations only, `make check` green at the end of
every phase).

Design record: `/Users/jan/.claude/plans/lets-go-deeper-on-enchanted-wand.md`
— read it first for full rationale on every decision below; this checklist
is the concrete execution of that plan.

**Scope note**: `docs/` has no existing placeholder for this feature.
`docs/500_transcript_model.md` §11/§16 anticipates it loosely ("selections
… not stored unless converted into: comments, exports, **future
annotations**"; "AI annotations" as a future extension) but nothing else
mentions it. Phase D8 adds a new spec doc plus targeted edits, mirroring how
`docs/1000_semantic_search.md` was introduced (`TODO_SEMANTIC_SEARCH.md`
Phase S7 is the template for that doc-update sequence).

Confirmed decisions (see the design record for the "why" behind each — do
not re-litigate these while implementing):
- **Access pattern**: a persistent global panel, docked in `AppShell` as a
  resizable column (not an overlay/drawer, not a dedicated-page-only flow)
  — it must stay open/reachable across navigation between
  ProjectView/SearchPage/ChatPage/VideoWorkspace so users can browse and
  write at the same time.
- **Document scope**: a project can have multiple named documents (like
  Google Docs), not a single scratchpad. Basic management (create, rename,
  list, delete, switch active document) is in scope for v1.
- **Insert behavior**: "add to document" always inserts a structured,
  non-editable **clip block** (video + token range + excerpt resolved fresh
  on read) — never a plain editable text paste. Users can add their own
  editable **note/caption** per clip, kept structurally separate from the
  excerpt.
- **Clip anchor resolution**: a clip block anchors to whichever transcript
  (original or translation) was on screen when the clip was selected —
  following the existing `Comment`/`CommentRange` pattern, **not** the chat
  citation's forced-resolve-to-original rule (which only works because chat
  citations operate on chunk-level time-overlap, not token-level alignment;
  there is no token-level alignment between an original transcript and a
  translation — see `app/services/translation.py` and
  `docs/500_transcript_model.md §13`). The excerpt is still always resolved
  fresh from that transcript's live tokens on read, so it can't drift.
- **Content storage**: one `content: JSONB` column per `Document` holding
  the TipTap/ProseMirror document tree (prose nodes + custom `clipBlock`
  nodes carrying `{nodeId, transcriptId, videoId, startTokenId,
  endTokenId, note}`). No separate block/position table — a rich-text tree
  doesn't fit the flat fractional-`position` pattern used by
  `TranscriptSegment`/`TranscriptToken`, and there's in-repo precedent for
  storing an editor/agent's own opaque JSON blob
  (`ChatConversation.agent_message_history`).
- **Concurrency**: whole-document optimistic locking via a `version`
  column + `expected_version` on every `PATCH` (mirrors
  `TranscriptToken.version`), not last-write-wins, not CRDT-level per-block
  locking. Acceptable for v1's single-user-at-a-time assumption; flag for
  revisit (different storage shape, e.g. Yjs) if true concurrent
  co-editing becomes a requirement.
- **Editor library**: **TipTap** (`@tiptap/react`, `@tiptap/starter-kit`,
  `@tiptap/core`) — the only realistic choice here for a custom node that
  renders a real interactive React component inline
  (`ReactNodeViewRenderer`), needed for the clip block card.
- **No new job type**: document CRUD and clip-block resolution are
  synchronous, like Comments — not async like Exports/embeddings.

## Phase D2 — Backend API (schemas, service, routes)
- [x] `backend/app/schemas/document.py`: `DocumentCreate{title: str}`, `DocumentUpdate{title: str | None = None, content: dict | None = None, expected_version: int}`, `DocumentSummary{id, title, updated_at}` (no `content` — keeps the panel's document-list fetch cheap), `DocumentRead{id, project_id, title, content, version, created_at, updated_at}` (`content` returned with every `clipBlock` node's `attrs` augmented with resolved display fields — see below), `ClipBlockResolveRequest{transcript_id: uuid.UUID, start_token_id: uuid.UUID, end_token_id: uuid.UUID}`, `ClipBlockRead{transcript_id, video_id, video_name, segment_id, start_token_id, end_token_id, start_time, end_time, speaker_name, language, excerpt, thumbnail_token, folder_path}` (mirrors `ChatCitation`'s shape/rationale in `app/schemas/chat.py`)
- [x] `backend/app/services/documents.py`:
  - `create_document(session, project_id, user_id, title) -> Document` — empty `content` (`{"type": "doc", "content": []}`), `version=1`
  - `list_documents(session, project_id) -> list[Document]`
  - `update_document(session, document, user_id, *, title, content, expected_version) -> Document` — raises a typed conflict error if `document.version != expected_version` (mirrors the `TokenMergeRequest`/token-version-conflict pattern); otherwise applies the update and increments `version`
  - `delete_document(session, document) -> None`
  - `resolve_clip_block(session, transcript_id, start_token_id, end_token_id) -> ClipBlockRead` — reuses the token-range lookup pattern from `services/comments.py`'s comment-range resolution (load `start_token`/`end_token`, derive `start_time`/`end_time`, compute `excerpt` from the tokens' displayed text in range, look up `video_name`/`speaker_name`/`language`/`folder_path`, mint a `thumbnail_token` via the existing media-token helper used in `chat.py`)
  - `resolve_document_content(session, document) -> dict` — walks `document.content` for every `clipBlock` node, batch-resolves the same fields as `resolve_clip_block` (avoid N+1 queries — batch-load tokens/videos/thumbnails/breadcrumbs in one pass, mirroring `app/api/routes/chat.py::_enrich_citations`), returns an augmented **copy** of the tree; never persists the resolved fields
- [x] `backend/app/api/deps.py`: add `require_document_access` — same two-step pattern as `require_transcript_access` (`db.get(Document, document_id)` → 404 if missing → `_require_membership(db, document.project_id, user)` → 403)
- [x] `backend/app/api/routes/documents.py`:
  - `POST /projects/{project_id}/documents` (editor floor) → `DocumentRead`
  - `GET /projects/{project_id}/documents` (viewer floor) → `list[DocumentSummary]`
  - `GET /documents/{document_id}` (viewer floor, `require_document_access`) → `DocumentRead` via `resolve_document_content`
  - `PATCH /documents/{document_id}` (editor floor) → `DocumentRead` or `409 CONFLICT` (typed error envelope, matching the existing token-conflict response shape)
  - `DELETE /documents/{document_id}` (editor floor) → `204`
  - `POST /documents/{document_id}/clip-blocks/resolve` (viewer floor) → `ClipBlockRead` — lets the editor populate a newly inserted node's attrs immediately without a full document round-trip
- [x] Register the new router in `backend/app/main.py` alongside the existing routers
- [x] Tests first (mirroring source): `tests/services/test_documents.py` (create/list/update-with-version-conflict/delete/resolve-clip-block/resolve-document-content, including a multi-clip document to check batch-resolution has no N+1), `tests/api/routes/test_documents.py` (mirrors `tests/api/routes/test_comments.py` shape — happy path for every route, non-member → 403, unknown id → 404, stale `expected_version` → 409, cross-project document id → 404 not leaked as 403)
- [x] Verify: `make check` green; all six routes present in the generated OpenAPI schema
